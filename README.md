
# Financial Management App — учёт личных финансов

Financial Management App — учебное SPA-приложение на JavaScript для управления личными финансами.

Приложение позволяет создавать счета, добавлять доходы и расходы, просматривать историю транзакций и отслеживать текущий баланс.

Проект выполнен индивидуально в рамках итоговой работы по модулю «Базовый JavaScript в браузере» Нетологии.

## Основные возможности

- Регистрация и авторизация пользователей.
- Создание, просмотр и удаление счетов.
- Отображение текущего баланса каждого счёта.
- Добавление доходов и расходов.
- Просмотр истории транзакций выбранного счёта.
- Удаление транзакций с подтверждением действия.
- Обновление финансовых данных без полной перезагрузки страницы.
- Отображение форм и модальных окон для выполнения пользовательских операций.

## Технологии

**JavaScript:** ES6+, классы, наследование, callback-функции, обработка событий.

**Browser API:** DOM API, XMLHttpRequest, FormData, URLSearchParams, localStorage.

**Дополнительно:** работа с JSON, обработка HTTP-ответов, форматирование дат и денежных сумм.

**Предоставленный интерфейс:** HTML5, CSS3, Bootstrap 3, AdminLTE.

**Предоставленная серверная часть:** Node.js, Express, lowdb.

Клиентская логика реализована без использования сторонних frontend-фреймворков.

## Техническая реализация

### Взаимодействие с серверным API

Для отправки HTTP-запросов реализовал функцию `createRequest` на основе XMLHttpRequest.

Функция формирует запрос, передаёт данные серверу и обрабатывает результат через callback-функцию.

Для GET-запросов параметры формируются с помощью `URLSearchParams`. Для отправки данных в теле запроса используется `FormData`.

В предусмотренном учебным заданием базовом классе `Entity` реализовал общие методы работы с API:

| Метод | Назначение |
| --- | --- |
| `list()` | Получение данных с сервера |
| `create()` | Создание новой сущности |
| `remove()` | Удаление сущности |

Классы `Account` и `Transaction` наследуются от `Entity` и используют общую логику взаимодействия с сервером.

**Ключевые файлы:**

- [createRequest.js](public/js/api/createRequest.js) — отправка HTTP-запросов и обработка ответов.
- [Entity.js](public/js/api/Entity.js) — общие методы взаимодействия с API.
- [User.js](public/js/api/User.js) — клиентская логика регистрации и авторизации.
- [Account.js](public/js/api/Account.js) — взаимодействие с API счетов.
- [Transaction.js](public/js/api/Transaction.js) — взаимодействие с API транзакций.

### Обработка форм без перезагрузки страницы

В базовом классе `AsyncForm` реализовал обработку отправки форм.

Стандартное поведение браузера отменяется с помощью `preventDefault()`.

Данные формы собираются через `FormData`, преобразуются в объект и передаются в обработчик соответствующей пользовательской операции.

После успешного выполнения запроса приложение обновляет необходимые данные интерфейса.

**Реализация:** [AsyncForm.js](public/js/ui/forms/AsyncForm.js)

### Динамическое обновление финансовых данных

При создании или удалении транзакции необходимо обновлять не только историю операций, но и отображаемый баланс счёта.

Для этого после успешного запроса используются предусмотренные классом `App` методы обновления соответствующих компонентов интерфейса.

Класс `App` и его методы обновления были предоставлены в учебном шаблоне. В ходе выполнения проекта реализовал их использование в обработчиках пользовательских операций.

Баланс рассчитывается на сервере, после чего актуальные данные повторно запрашиваются и отображаются в интерфейсе.

### Обработка событий динамических элементов

Список транзакций формируется после получения данных с сервера.

Для обработки действий пользователя реализовал делегирование событий: обработчик зарегистрирован на общем контейнере страницы транзакций.

С помощью `closest()` определяется выбранный элемент, а идентификатор транзакции считывается из атрибута `data-id`.

Это позволяет обрабатывать нажатия на кнопки элементов, добавленных после первоначальной загрузки страницы.

**Реализация:** [TransactionsPage.js](public/js/ui/pages/TransactionsPage.js)

### Работа с состоянием авторизации

В классе `User` реализовал сохранение информации о текущем пользователе в localStorage.

При открытии приложения выполняется запрос к API для получения актуальной информации об авторизованном пользователе.

В зависимости от ответа сервера обновляются локальные данные и состояние интерфейса.

При выходе информация о пользователе удаляется из localStorage.

Управление серверной сессией выполняется предоставленной серверной частью приложения.

## Установка и запуск

Для локального запуска необходимы Node.js и npm.

**1. Клонируйте репозиторий**

```bash
git clone https://github.com/potykalov/financial-management-app.git
cd financial-management-app
```

**2. Установите зависимости**

```bash
npm install
```

**3. Запустите сервер**

```bash
npm start
```

После запуска приложение будет доступно по адресу:

http://localhost:8000

Для проверки можно использовать демонстрационную учётную запись:

**Email:** `demo@demo`  
**Пароль:** `demo`

Также можно зарегистрировать нового пользователя.

## Тестирование

В учебном шаблоне предусмотрены тесты Jasmine для проверки отдельных компонентов взаимодействия с серверным API.

Тестовые файлы расположены в каталоге [public/test/spec/api/](public/test/spec/api/).

Они содержат проверки функции `createRequest` и классов `Entity`, `User`, `Account` и `Transaction`.

В текущей конфигурации проекта команда `npm test` не настроена для запуска этих тестов.

Автоматический запуск тестов через GitHub Actions не настроен.
